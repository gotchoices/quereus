# `cardinality_feedback()` and user-facing docs — review handoff

Fifth of the `cardinality-feedback-*` chain (design: `docs/progressive-optimizer.md` §3.9).

## What landed

- **TVF `cardinality_feedback()`** (`src/func/builtins/cardinality-feedback.ts`, registered after `lensAdvisoriesFunc` in `index.ts`). Zero args, `deterministic: false`, key `(schema_name, table_name)`. Columns: `schema_name`, `table_name`, `observed_rows`, `catalog_rows` (nullable), `baseline_rows`, `observations`, `shifts`. Body reads `db._cardinalityFeedback.snapshot()` (already identity-filtered; shape matched the columns, no manager change needed), sorts by schema then table with `localeCompare`. No `db.eval`/`db.exec` in the body.
- **Logging**: `core:cardinality-feedback` now logs each shift (`Shift on <key>: baseline X -> Y rows`, in `record()`) and each feedback re-plan (`statement.ts` `dropPlanOnShift`, moved off `core:statement` onto a `feedbackLog` with that namespace). Per-record/drop/discard lines remain on `core:cardinality-feedback:debug`. `database.ts`'s publication-failure warning stays on its own warn logger.
- **Docs**: `functions.md` (table row + columns subsection), `usage.md` (option row: plan depends on session history, points at the TVF; default/clears were already there), `sql-txn.md` §9.5 (paragraph on ANALYZE superseding observations, observations covering tables auto-analyze skips), `progressive-optimizer.md` §3.9 (present tense, logging namespaces updated).

## Test added

- `test/optimizer/cardinality-feedback.spec.ts` › `cardinality_feedback()` › one prepared `select table_name, observed_rows from cardinality_feedback()` returns `[]`, then after a full `select v from big` of 20,000 rows returns `[{ table_name: 'big', observed_rows: 20000 }]` without re-preparing.

## Known gap — for the reviewer to weigh

- The test does **not** discriminate the deterministic flag: I flipped it to `deterministic: true` and the test still passed. Today nothing constant-folds or caches a TVF's rows at plan time, so the flag is defensive (CSE / fingerprint / MV-rewrite paths read determinism). The test still verifies the end-to-end path (real scan → publication → TVF at execution time). Reviewer may decide to keep it as-is, or cut it if judged not to pay for itself.
