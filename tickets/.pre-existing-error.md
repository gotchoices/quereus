## Why pre-existing

The test asserts that `alter table src alter column a drop not null` leaves a maintained table keyed on `a` live. Commit `994ed95bf` (debt-mv-ordering-seed-to-materialized-index) deliberately changed that: a `drop not null` on a column the backing key leads with now marks the view stale until `refresh` (see `tickets/complete/debt-mv-ordering-seed-to-materialized-index.md`, "Behaviour" paragraph). That ticket's validation ran only the `@quereus/quereus` suite, not the `@quereus/store` workspace tests. The ticket that surfaced this (debt-schema-change-notice-must-carry-registered-schema) does not touch the ALTER COLUMN or staleness paths, and a debug-logged run of the single test shows no error raised by its new notifier check.

The likely resolution is to update the test's expectation (stale after the loosening; `refresh` then reshapes the key column in place) rather than the engine. `backlog/feat-mv-drop-not-null-loosens-backing-in-place` would restore the old expectation if it lands.
